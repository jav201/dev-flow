# Changelog

One entry per flow revision shipped to this repository. The flow's full revision log stays in the private canonical repository; this file records what a user of the published skill receives.

## 2026-09-25-rev94 — the record is checked against the transcript, the count and the tree

- **A packet that reports a test run now has to cite that run's transcript, and the number it reports is read back out of those bytes.** Before this revision you could write `4 passed` in an increment packet, cite no evidence at all, and the gate would agree with you — `none — this increment cites no evidence file` was a legal answer whatever the packet claimed above it, so the rule that re-hashes evidence had nothing to hash. It is now a refusal: wherever a packet reports `N passed` / `N failed`, or ticks the evidence-checklist row that says the tests pass, the run's own output belongs under the batch's declared evidence home, cited with its SHA-256. The declared empty stays legal exactly while the packet reports no run. And the figure is compared: a packet claiming more passes than its own cited transcript holds is refused, with both numbers printed. Claiming fewer failures than the evidence shows is reported, not refused — the evidence you are asked to keep includes captures that fail on purpose.
- **This applies in every mode, and it is not the fast path being made stricter.** The long packet admitted the same empty, and the batches that produced this flow cited no evidence files for eight consecutive batches, so the check had never had a subject there either. One rule, one obligation, all three modes.
- **The close now records which tree it gated**, as one new row: the commit the gate ran over, and whether the working tree was clean. Every later run says out loud when that record no longer describes what is on disk — `record predates this tree by N commit(s)`, or the files that are dirty against it. **This is a notice and never a refusal.** A closed batch is allowed to be followed by work; what was missing was not a veto but a sentence, because until now a gate re-run over a changed tree printed exactly the verdict it printed over the original one. Expect `predates this tree by 1 commit(s)` right after a close: the commit carrying the record is itself one commit later than the tree it names, and the figure is the record's age.
- **What this does not catch, stated plainly rather than left to be assumed.** A transcript regenerated from tests that assert nothing hashes correctly and reads correctly. Rewrite every assertion to something that cannot fail, re-run the suite, store the output, cite it — and all three of the checks above pass. Only a mutation battery sees that, and which modes owe one has not changed. What this revision gives you is **a record a tool can check against the tree**. That is a different and smaller claim than *a record that cannot be faked*, and the repository's own tagline is changed to say so.
- Two smaller repairs from the same measurement: the batch-declaration script's closing hint used to publish an order of work that contradicted the command it hands you off to, and now names that page instead of restating it; and the backlog's recorded base ref is stated to be the commit the batch started from, never the commit that carries the update — which would be a record of itself.
- The measurement behind all of the above was an external tamper test across five agent engineering kits. On a closed toy project, three separate tampers — changed code, hollowed-out tests, an edited test count — each left this flow's verdict byte-identical to the clean run. Two of the three now change it.

## 2026-09-24-rev93 — the selftest passes on the machine this README tells you to build
- `scripts/devflow-validate.py --selftest` now exits 0 when this bundle is installed the way the README says to install it — `dev-flow/` and `dev-flow-lessons/` copied into a `.claude/skills/` folder. It did not before. On a machine that also holds an authoring tree, one population was read twice — once from this bundle and once from the tree beside it — and the arm that counts it exited 1. Continuous integration could not see it, because a runner has no such tree; the previous revision's own checks could not see it, because they measured a bundle with nothing beside it. The defect lived exactly between the two machines that were armed.
- Three machines are declared and all three are now run by the suite on every change: an authoring tree, a bundle with nothing beside it (what CI runs), and a bundle installed beside an authoring tree (what a reader has). The third is required to produce the same exit code and the same named SKIP set as the second. An independent review then found one more check still reading the tree beside the bundle rather than the bundle — the same defect one check over, caught by reading the two machines' transcripts side by side — and it is fixed here too.
- A population this tool reads is now a set keyed by the file's flow-relative name, and reading one name twice is a failure that prints both paths rather than a duplicate silently collapsed. The control is driven by a planted collision, so it is known to be able to fail.
- The adapter's published skip census is 30 names over 32 lines (34 over 36 where there are no drive letters).
- The workflow this repository's continuous integration runs is generated from a file that is now inside the flow's hashed manifest upstream, so weakening it **at its source** moves the flow hash and a check reads it. Editing the copy in this repository still changes nothing upstream, and no check here can see that — said plainly rather than left to be assumed.
- One commit per revision, and the entry below records where that already slipped: rev92 landed here twice, under two different flow hashes.

## 2026-09-24-rev92 — the selftest passes on a machine that has never held a canon home
- `scripts/devflow-validate.py --selftest` now exits 0 from a clean checkout of this repository. It did not before: on GitHub Actions, ubuntu-latest, Python 3.11, it printed 50 failing arms and then died with `FileNotFoundError` on a path under `~/.claude`. Every one of those arms passed on the author's machine, because that machine has the private authoring tree the arms were silently reading.
- One resolver now answers "where does this flow live" for both layouts. Templates, commands, agent roles, the manifest and the control catalog are read from the bundle you installed. A subject that only the authoring tree can hold — a live project record, a second checkout, the whole Python file set, the diagram directory — makes the arm print a named SKIP saying what was not measured and why, and a closing line counts those skips by subject. None of them is scored as a pass.
- The adapter publishes the full list of arms that skip in a bundle (28 names over 30 lines, grouped by the missing subject), and an arm compares both numbers against a real bundle run in both directions.
- The selftest checks its own flow home before its first arm. A skill install is `dev-flow/` and `dev-flow-lessons/` side by side; if something is missing, the run says which folder, says it measured nothing, and exits non-zero — instead of running every check against a population that is not there.
- The selftest's own bundle run is now started with an empty `HOME` and no `DEVFLOW_*` variables, so the authoring tree cannot stand in for the tree being measured, and a new arm requires that no arm be red in that run and green in the parent's.
- Continuous integration on this repository runs the selftest in bundle mode and the gate on an empty tree on every push — and its first run found a second problem of the same kind: the checks assumed the machine they were written on. Two of those were real defects in the flow, not in the tests. `V40` rejected every checkout identity on any system without drive letters, so on Linux and macOS it refused what it was supposed to accept; and the loader that resolves a batch's artifacts walked the directory in whatever order the filesystem returned, so two copies of one repository could resolve different documents for the same filename. Both are fixed, and the checks that would have caught them are now written against the rule rather than against one machine.
- The list of arms that skip in a bundle differs by platform, and the adapter now publishes both counts.
- Note on this repository's history: two commits claim rev92 with different flow hashes. The first export landed before rev92's second review pass; the second is the revision as it was finally released, and it is the one this entry describes.

## 2026-09-21-rev91 — authorization on runtimes that cannot prompt
- On a runtime with no prompts, the operator's initial commission is the batch's standing authorization, declared in the spec header at Phase A; the guided gate records its decision instead of waiting for one, and a gate that was actually asked writes `asked at the gate`.
